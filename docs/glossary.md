# Glossary

Every term this system uses: what it means, and where it appears in the code, the schema or on the wire. It is for
everyone who reads or writes the documents and the code. Updated 2026-11-26.

**Why it exists.** The same idea kept acquiring second names, and two of them had genuinely collided: "session"
meant both an authenticated lobby session and a player's stay in an arena. That is how someone eventually believes
that losing one ends the other.

**How to use it.** If a word is here, use it as defined, and for nothing else. If you need a word that is not here,
add it here first. The [naming rules](README.md#naming) come before this list: the one word they exclude is used
nowhere, in prose or in identifiers.

**How to read it.** Each row has three columns: the **term**; its meaning, a plain definition first and then the
detail; and **where** it is realised in code, in the schema or on the wire. There are nine sections: processes and
places (§1), play (§2), people and identity (§3), the world (§4), results and reward (§5), on the wire (§6), store
keys (§7), words we do not use (§8), and building, checking and running (§9).

## 1. Processes and places

| Term | Meaning | Where |
|---|---|---|
| **backend** | The whole system. Also the namespace for everything: packages, paths, units, the OS user. | `com.backend.*`, `/opt/backend`, `backend-arena@a1` |
| **arena** | A process that runs the match simulation. It speaks to clients over its own binary protocol, not through the gateway; on the site it sits behind the **front**'s nginx (D-82). Also, loosely, the place where a match happens. | `arena` module, `ArenaMain`, `arena:{name}` |
| **platform** | The process that serves everything between matches: accounts and guests, sessions, tickets, the matcher, teams, tournaments' registration, the boards, the shop and payments, the social layer, and the admin API. | `platform` module, `PlatformHttpServer`, `AdminServer` |
| **gateway** | The process that holds the clients' lobby connections and forwards them to `platform`. It makes no product decisions. | `gateway` module, `GatewayServer` |
| **worker** | The process that applies match results to MySQL and grants the rewards. | `worker` module, `WorkerMain` |
| **front** | The one machine that the site's public address is forwarded to. Its nginx takes every player's connection on 80, 443 and 9001, ends the TLS on 443 and 9001, and passes each connection over the private network: the API, the account service's routes and the lobby to the machines' platforms, account services and gateways, and a match to the arena its **TLS name** names, or, on 80, the name in `/match/<name>` (D-115). It is C in the examples. Every machine's nginx is set up the same way, so any machine can be made the front ([D-82](architecture/03-decision-log.md#d-82--one-public-address-for-the-site-nginx-in-front-ending-tls-routing-match-traffic-by-name)). At launch the one machine is the front and everything else, and its nginx passes to its own processes on loopback (D-93). | `backend-nginx`, `backend-stream.conf`, `backend.conf`, [operations/05](operations/05-ports-and-firewall.md) |
| **standby** | The second machine of two, B ([D-96](architecture/03-decision-log.md#d-96--a-second-machine-is-the-first-ones-standby-the-replicas-and-a-front-ready-to-start)). It runs MySQL's and both stores' replicas, and holds everything else of the first machine installed from its files and stopped, to be started in its place when the first machine is lost. | [operations/10](operations/10-two-machines.md) |
| **trusted proxy** | An address whose `X-Forwarded-For` header the platform and the gateway believe: the machines' nginx. It lets a player's own address, not the front's, key the login limits and the logs. A header from anyone else is ignored. | `BACKEND_TRUSTED_PROXIES`, `TrustedProxies` |
| **handoff** | The module that holds what `platform` and `arena` both touch, and nothing else. It exists so that `arena` never inherits a database driver. | `handoff` module |
| **room** | One simulated world inside an arena, with its own thread and its own players. An arena hosts several. | `Room`, `RoomThread`, `RoomRegistry` |
| **store** | j-redis, the data store. It runs as two instances of one binary ([D-7](architecture/03-decision-log.md#d-7--two-j-redis-instances-not-one)): **session** holds the sessions, tickets, the arena directory, throttles, the gateway registry, the queues, parties and leases, and the score boards; **events** holds the result stream and the lists beside it. With `BACKEND_EVENTS_STORE` unset, one instance is both. The instance named *session* is not a **session**. | `j-redis-service`, `StoreClients` |
| **primary** / **replica** | Of a stateful role (MySQL, or either store): the **primary** is the server that takes writes; a **replica** is the copy on another machine that follows it and takes none. | `replicaof`, `super_read_only`, `BACKEND_STORE_ADDRESSES`, `BACKEND_DB_URL` naming two hosts |
| **promotion** | Making a replica the primary. An operator does it with a script, never automatically ([D-8](architecture/03-decision-log.md#d-8--failover-is-scripted-not-automatic)). | `promote-store.sh`, `promote-mysql.sh`, [runbook §2](operations/02-runbook.md#2-stateful-primary-failure) |
| **epoch** | A number that only a promotion raises. A process never uses a primary whose epoch is below one it has already seen, so an old primary that comes back is passed over. | j-redis `ROLE`, MySQL's `ha_epoch` |
| **heartbeat** | The one row (`ha_heartbeat`) that every `worker` stamps on MySQL's primary once a second. A replica's copy of the row is as far as the replica has applied, so the primary's stamp less the replica's is the replica's lag ([D-58](architecture/03-decision-log.md#d-58--a-replica-is-measured-by-what-it-has-applied-a-heartbeat-for-mysql-the-primarys-own-account-for-the-stores)). | `V1__schema.sql` (V21 before the squash, D-75), `ReplicaWatch`, `promote-mysql.sh` |
| **fence** | To stop an old primary serving before its replica is promoted: it is stopped, or cut off, or, in a **handover**, made read-only and closed to the processes by the script. | `--old-is-down`, `--demote-old` |
| **handover** | A planned promotion: the old primary is still up, and the script fences it. The opposite of a promotion that follows a failure. | `MYSQL_FAILOVER=demote` in the drill |
| **arena directory** | The list where `platform` and `worker` find arenas. Each arena announces its host, port and load every 3 s, and an entry is kept 10 s; the matcher chooses from it (D-20, D-42). | `ArenaDirectory`, `arena:{name}`, `arenas` |
| **lease** | A store key taken with `SET NX` and an expiry, so that one process of many does a job. It is given back when the job is done, or left to lapse: the matcher's, the ledger check's, the season's close. It is not a fencing token: each job it guards is safe to repeat ([availability §5](architecture/02-availability.md#5-prerequisites-still-missing)). | `mm:leader`, `job:ledger-check`, `job:season` |
| **drain** | How an arena stops: it leaves the directory, sends the public arena's players back to the lobby with their results, and lets made matches end, for up to eleven minutes ([01 §8.6](detailed-design/01-arena.md#86-draining-an-arena-designed-2026-09-29-plan-item-7), D-29). | `systemctl stop`, `drained in N s` |
| **admin API** | `platform`'s interface for the operator. It has its own listener, on loopback, behind a bearer token, and every call is audited in MySQL ([04 §10](detailed-design/04-platform-services.md#10-admin-api), D-30, D-50). | `AdminServer`, `BACKEND_ADMIN_ADDR`, `/admin/*`, `admin_audit` |
| **clone** (a server) | To make a MySQL replica, or remake an old primary as one, by copying a whole server from the primary with MySQL's clone plugin: its data, accounts and GTID history, never its persisted settings ([D-36](architecture/03-decision-log.md#d-36--a-mysql-replica-is-made-and-an-old-primary-remade-by-clone)). | `CLONE INSTANCE`, [01 §9](operations/01-deploy.md#9-mysql), runbook §2 step 5 |

## 2. Play

| Term | Meaning | Where |
|---|---|---|
| **match** | The umbrella term: **one recorded unit of play**. Always qualify it as *open* or *timed* when the difference matters. | `matches` table, `MatchOutcome` |
| **open match** | A recorded **stay** in the public arena, or, for a stay longer than ten minutes, one ten-minute piece of it (**checkpoint**). It has no roster, no placement and no winner. The room never resets ([D-15](architecture/03-decision-log.md#d-15--the-public-arena-runs-continuously-structured-modes-are-timed-matches)). | `MatchOutcome.KIND_OPEN`, `matches.kind = 0`, `MatchRules.Lifecycle.OPEN` |
| **timed match** | A contest with a fixed roster, a start and an end, and one result for everybody. Every mode but the public arena's is timed, tournament matches included. | `MatchOutcome.KIND_TIMED`, `matches.kind = 1`, `MatchMode.timed` |
| **public arena** | The free-for-all room that every arena runs without end. Players join it with "play now", with no queue, and their results are **open matches** (D-15). | `MatchMode.FFA`, `Lifecycle.OPEN` |
| **made match** | A timed match that `platform` or `worker` makes for a roster: by the matcher, for a tournament's round, or for a sandbox request. The arena makes its room from the first ticket that names it (D-20). | `Lifecycle.MADE`, `matchUid` |
| **battle** | The **activity**, never a unit: "in battle", "battle rewards", "the in-battle ratio". Good for wording the player sees. | prose, UI labels |
| **combat** | **Not used as a unit.** It is a mass noun ("a combat" reads wrongly), and it names the shooting, not the bounded contest. Acceptable as a heading inside code. | — |
| **checkpoint** | Closing a long open match and starting a fresh one for the same player, every ten minutes, so that a long stay is paid for before it ends. | `MatchRules.checkpointTicks`, `MatchTally.checkpointOpenMatch` |
| **life** | One tank, from spawn to death. It is **not** a recorded unit: a result per life would be about 1 700 events a second at 50 000 players. | `Entity`, respawn |
| **mode** | The rules of a match: its map, its win condition, its teams. There are ten: `ffa`, the public arena; `duel`; `tvt`, team-vs-team, three against three; `rffa`, ranked free-for-all, eight players; `coop`, three against waves; `teams`, a **team match**; `domination`; `tag`; `maze`, eight players each for themselves among walls; and `sandbox`. All but `ffa` are timed, and all but `ffa` and `sandbox` are queued. | `matches.mode`, `MatchMode` |
| **wave** | In co-op: a group of the arena's own **hunting tanks**, which go for the nearest player of another team. The next wave comes once the last one is dead ([01 §8.5](detailed-design/01-arena.md#85-co-op-waves-designed-2026-09-29-plan-item-6)). A **wipe** is when none of the players' team is alive at once. | `arena/Waves`, `Entity.hunts` |
| **queue** | Where players wait for a timed match of one mode, oldest first. Not the result queue of §7. | `mmq:{mode}`, `MatchQueue` |
| **entry** (queue) | What the queue holds and the matcher places: a player alone, or a **party** under its leader. An entry is queued, taken out and matched whole. | `mmp:{playerId}`, `MatchQueue.Waiting` |
| **matcher** | The loop that makes matches out of the queues, once a second. Whichever `platform` holds the lease runs it. | `Matchmaker`, `mm:leader` |
| **rating window** | How far apart in rating the matcher lets entries be matched: ±100, and 50 wider for every 10 s that the oldest entry has waited. Not a board's **window**. | `Matchmaker.window` |
| **rating** | A player's Elo score in one rated mode. It starts at 1 200 and is moved by placement. A **side** in team-vs-team is rated as its players' mean ([D-26](architecture/03-decision-log.md#d-26--a-team-is-rated-by-its-players-mean-each-moved-by-their-own-k)); in a free-for-all, each player is rated against each other ([D-28](architecture/03-decision-log.md#d-28--a-free-for-all-is-rated-pairwise-each-player-against-each-other)). A **team** has a rating of its own, moved only by team matches (Q-18). | `player.rating_duel`, `rating_tvt`, `rating_rffa`, `team.rating`, `worker/EloRating` |
| **confirm step** | Asking every player of a match found whether they are coming, before the match is made. Each has ten seconds to accept; a decline, or silence, calls the match off ([D-27](architecture/03-decision-log.md#d-27--a-match-found-asks-every-player-before-it-is-made)). A player being asked is **confirming**. A player whose party changed meanwhile has **withdrawn**: that entry is out of the match, and nobody is locked out (T-32). | `evt.match.ready`, `Matchmaker.settle`, `mmc:{matchUid}` |
| **walkover** | A timed match that one side wins because the other side never came. It moves no rating, is not a rated match, and pays no match coins. Lasting no time, it counts toward no stats, achievements, goals or pass points either (defect D-45 and decision D-76, the owner's, 2026-10-05; before then it counted as a win, as defect T-44 records). It is recorded, and it decides a tournament's match. | `RoomThread.startMadeMatch` |
| **party** | Up to three players who queue together. It is made by an invitation, and lives in the store only ([D-25](architecture/03-decision-log.md#d-25--a-party-lives-in-the-session-store-and-only-its-leader-queues)). Its **leader**, its first member, queues it. Not a clan. | `party:{id}`, `Parties`, `evt.party.*` |
| **tick** | One simulation step. There are 25 per second. | `Room.tick()` |
| **experience** (xp) | What killing something is worth. The same number levels the killer's tank and adds to their match score, so a player is never shown two scores that disagree. | `KillLog.xp`, `TankStats.xp` |
| **level** | A tank's progression **within one life**, from 1 to 45. It is lost at death, except for the **level rebate**; the match score is not lost. | `TankStats.level`, `F_LEVEL` |
| **level rebate** | What a tank respawned after a death keeps. In the public arena: a quarter of the experience its last life reached, up to what level 20 needs. In a made match: none, level 1 (Q-36). | `RoomThread.respawn` |
| **class** / **class table** | A **class** is what a tank is: its barrels, reload, view and body. There is Basic, and 48 more opened at levels 15, 30 and 45, chosen with `ChooseClass`; and the arena's own classes (the Guardian, the dominator), which no player can choose. The **class table** lists them. `platform` serves it, versioned by its content ([D-24](architecture/03-decision-log.md#d-24--the-class-table-reaches-the-device-from-platform-versioned-by-its-content)). | `ClassTable`, `GET /v1/content/classes` |
| **class tier** | The classes that one level opens: the first tier at 15, the second at 30, the third at 45. Not a season pass's **tier** (§5). | `ClassTable` |
| **barrel** | One gun of a class: its angle, offset and delay, multipliers for a bullet's speed, damage and penetration, its spread and lifetime, fired in volleys ([01 §4](detailed-design/01-arena.md#4-levelling-xp-tank-tree)). Also the name of an equipment **slot**. | `ClassTable.Barrel` |
| **unit** | Something a class makes that is steered, not predicted: drones, traps, minions and missiles. Units are streamed as tanks are, and drawn by their create's radius. | `Entity.WIRE_UNIT` |
| **skill point** | A point granted on levelling, spent to raise one stat. A tank has 33 by level 45, and at most 7 go in any one stat, so four stats can be maxed and a fifth cannot. | `TankStats.unspentPoints`, `ClientMessage.UPGRADE_STAT` |
| **stat** | One of the eight numbers a player can upgrade: health regen, max health, body damage, bullet speed, penetration, bullet damage, reload, movement speed. Their order is a wire contract. | `Stat` |
| **effective stats** | A tank's stats after its level and points are applied. They are recomputed when something changes, never per tick. | `TankStats.refresh` |
| **content table** | Balance as data rather than code: what a stat is worth, what a level costs, what shapes exist. There is one set per arena, fixed while a room runs. | `Content`, `StatTable`, `LevelTable`, `ShapeTable` |
| **phrase** | What a player can say: one of a fixed list, sent as its id, never as free text ([D-14](architecture/03-decision-log.md#d-14--communication-is-a-fixed-phrase-list-never-free-text)). In a mode with teams, the speaker's team hears it; otherwise, those who can see the speaker. The list is content, versioned by its hash. | `PhraseTable`, `ClientMessage.PHRASE`, `Wire.EVT_PHRASE` |
| **shape kind** | Which shape a shape is: square, triangle, pentagon or alpha pentagon. The kinds differ in size, health and experience. Its id is on the wire as the static entity's subtype. | `ShapeTable.Type`, `Entity.subtype` |
| **snapshot** | One outgoing frame of world state, for one client. 15 per second, 10 at the `saver` profile. | `SnapshotEncoder`, `Wire.MSG_SNAPSHOT` |
| **stay** | One player's continuous presence in one room: from `Join` to `Leave`, a kick, the arena stopping, or the end of a lost connection's wait, across any number of **resumes**. An open match records a stay, cut into ten-minute pieces by checkpoints. | `MatchTally`, `backend_arena_stays_*` |
| **waiting stay** | A stay whose connection was lost. Its tank is **parked** for 10 s, then taken out of the world with its level and points kept, until a resume, or for 60 s. Its play time stops meanwhile. The code calls it *suspended*. | `RoomThread.Suspended`, `MatchRules.resumeGraceTicks`/`resumeKeepTicks`, `backend_arena_stays_waiting` |
| **resume** | Coming back to a waiting stay, on a new connection to the same arena, with `Resume` and the resume secret. An app that is killed and restarted resumes the same way, with the secret it kept on the device: the lobby hands nothing back ([D-18](architecture/03-decision-log.md#d-18--a-lost-connection-waits-in-the-arenas-memory-not-the-store), [D-51](architecture/03-decision-log.md#d-51--a-cold-resume-is-the-devices-the-app-keeps-its-stays-secret)). | `ClientMessage.RESUME` (10), `RoomThread.resume` |
| **resume secret** | 128 random bits in every `Welcome`, spent by one `Resume`. Each `Welcome` carries a new one. It is held in the arena's memory, not in the store. | `Connection.resumeSecret` |
| **parked** | Said of a tank in the world that no input drives: the app is in the background, its input has been silent for a second, or it is waiting for a resume. A parked tank can still be killed. | `RoomThread` (`STALE_INPUT_NANOS`), [P-23](defects.md#2-protocol--the-client-contract) |

## 3. People and identity

| Term | Meaning | Where |
|---|---|---|
| **account** | Two things, kept apart by where they live. At the account service, the login: a username and a password hash (D-117). In the backend, whose a player is: the account service's **subject**, or a guest's key. There is one per player. | `account` tables of both databases, `AccountRepository` |
| **account service** | The system that signs a person up and in, apart from the backend (D-117; designed 2026-11-26, built in plan item 142): a username, a password, and the tokens it issues. It owns no player. | `account-service/`, `com.backend.account`, the database `account` |
| **access token** | A JWT the account service signs (ES256, `typ` `at+jwt`), good for 15 minutes, that proves who is logging in. The backend takes it once, for a **session**; it is not a session. | `POST /v1/sessions` `{"accessToken"}`, `AccountTokens` |
| **refresh token** | An opaque token from the account service that the app keeps, in place of a password, to get a new access token; spent at each use, and a new one given. | `refresh_token` table, `POST /account/v1/sessions/refresh` |
| **subject** | The account service's id for an account, the tokens' `sub`: what ties an account to its player. Never reused. | `account.subject` (the backend's), `sub` |
| **account event** | A signed notice from the account service that an account was deleted or its sessions revoked (a Security Event Token, RFC 8417), pushed to the platform until taken. | `event_outbox`, `POST /v1/account-events` |
| **player** | The person in the domain: their name, level, currency and stats. A player shares its id with its account. | `player` table, `playerId` |
| **account level** | A player's level across matches, from 1 to 100, from their lifetime experience; what later features unlock by. It never goes down. Not the **tank level** (1 to 45), which lasts one life. | `player.level`, `AccountLevels` |
| **session** | **The authenticated lobby session, and nothing else.** A token is issued at login, and is valid for about a day. Never use the word for a player's time in an arena: that is a **stay**, recorded as one or more open matches. | `sess:{token}`, `SessionStore` |
| **ticket** | A single-use, short-lived credential that lets one player into one arena. It is claimed atomically, and destroyed on use. | `ticket:{id}`, `Ticket`, `TicketStore` |
| **connection** | One client socket on an arena. It is the boundary between the Netty threads and the room thread. | `Connection` |
| **player tag** | A number that identifies a player inside one room, never reused. Kill credit travels by tag, because a pool slot can be reused by someone else while a bullet is still in the air. | `Entity.playerTag` |
| **handle** | A one-byte alias for an entity, per client, so that the wire never carries a 32-bit id. | `ClientView`, `Wire.MAX_HANDLES` |
| **display name** | The name other players see: 1 to 16 characters, in any script, checked by `DisplayName` when a first login names the player and at a rename (once in 30 days, [04 §1](detailed-design/04-platform-services.md#1-auth-and-sessions)). It need not be unique. It is distinct from the **username**, which is what you log in with at the account service (ASCII, never shown to others), and from which a first login takes the display name when the rules allow it. | `player.display_name` vs the account service's `account.username` |
| **erased account** | An account that its player deleted (D-84), here as a guest or at the account service (D-117), or a guest nobody played for 180 days (D-87). Its status is 3, `DELETED`; it has no subject or guest key, and a deleted account's subject is kept in `erased_subject`, so its late token makes no player; its display name is `Deleted player`; and the players it knew and its places on the boards are gone. Its rows in others' history and in the ledger stay, under the bare id. | `AccountRepository.erase`, `AccountDeletion`, `DELETE /v1/accounts`, `POST /v1/account-events`, `worker/IdleGuests` |
| **public code** | A unique twelve-character code that every player is given, meant to be shared. No API shows it yet: friends are asked for by player id (Q-20). | `player.public_code` |

## 4. The world

| Term | Meaning | Where |
|---|---|---|
| **entity** | Anything in the simulation with a position: a tank, a bullet, a shape. Entities are pooled, never allocated during a tick. | `Entity`, `World` |
| **tank** | A player's or a bot's vehicle. | `Entity.KIND_TANK` |
| **bullet** | A projectile. The client simulates it from its creation; it is not streamed ([D-9](architecture/03-decision-log.md#d-9--deterministic-entities-are-simulated-by-the-client)). | `Entity.KIND_BULLET`, `WIRE_PREDICTED` |
| **shape** | Neutral scenery that can be shot for score. | `Entity.KIND_SHAPE`, `WIRE_STATIC` |
| **side** | One side within a match: 1 and 2 in team-vs-team, and 0, every player's, in a mode without teams (the public arena, a duel, a free-for-all). The code and the documents before 2026-09-30 write it `team`; since then **team** means a lasting group of players, so the code keeps its name and the documents say *side*. | `Entity.team`, `match_player.team`, `Ticket.team` |
| **view** | The rectangle of the world that one client can see, and the handle table for it. | `ClientView` |
| **interest management** | Choosing which entities are worth sending to a given client, within a budget. | `SnapshotEncoder` |

## 5. Results and reward

| Term | Meaning | Where |
|---|---|---|
| **outcome** | What the arena reports about a match: who played, what they killed, how long. **Facts only**, never what they are worth. | `MatchOutcome` |
| **reward** | What those facts are worth, in experience and currency. `worker` alone decides it, so a change of balance is one deploy, and never two arenas that disagree. | `RewardRules` |
| **placement** | A player's finishing position in a timed match. It is **0 in an open match**: there is no field to be placed in, and a number there would look meaningful and not be. | `match_player.placement` |
| **score** | The points earned within one match. Shapes and tanks are worth different amounts. | `match_player.score` |
| **assist** | A hit on a tank by a player, within the five seconds before another player killed it. It is worth a quarter of the kill's experience, and is counted with the match's and the player's totals ([01 §7](detailed-design/01-arena.md#7-deaths-respawn-spectate), plan item 65). Not a kill. | `TankStats.attackerTags`, `KillLog.assists`, `match_player.assists` |
| **kill / death** | A death is always recorded; a kill only if the killer is still in the room. So the totals satisfy *kills ≤ deaths*, never equality: bullets outlive the player who fired them. | `MatchTally.applyKill` |
| **kind** | Which lifecycle produced a recorded match. It is stated in the row, rather than inferred from the placement. | `matches.kind` |
| **ledger** | The append-only record of every currency movement. The balance must always be derivable again from it. | `ledger` table, `EconomyRepository` |
| **offer** | One thing the shop sells, named by its **sku**: an item, a price in coins or gems, and, optionally, a level it needs and a time it is on sale. Offers come from `shop.json`, read at start. | `Catalogue.Offer`, [04 §8](detailed-design/04-platform-services.md#8-economy-shop-inventory-and-equipment) |
| **purchase key** | The client's transaction id for one tap of Buy, a lowercase UUID. It is sent again, unchanged, with every retry of that tap, so the tap is charged once. | `ShopService`, `ledger.idem_key` as `buy:{playerId}:{key}` |
| **item** | Something a player can hold, defined in `items.json` on `platform`: an id, a type (**equipment**, **boost** or **skin**), and what it does. What a player holds is `inventory_item`. | `Items`, [04 §8](detailed-design/04-platform-services.md#equipment-designed-2026-09-30-plan-item-15) |
| **equipment** / **slot** | **Equipment** is an item worn in one of four **slots**, one each: barrel, armor, core and treads. It gives a whole percent in one to three stats. (A **skin** has a fifth slot of its own, and gives nothing.) | `equipment` table, `/v1/equipment`, `EquipmentService` |
| **loadout** | What a player wears: in each slot, an item or nothing. | `GET /v1/equipment` |
| **bonus** (equipment's) | What a loadout gives: a percent added to each stat, capped at 25 %. It means "better by that much", so for reload it is that much more shots. It is resolved on `platform`, carried in the ticket to the arena, and put on every tank the player spawns ([D-37](architecture/03-decision-log.md#d-37--equipment-reaches-the-arena-as-a-capped-percentage-a-stat-in-the-ticket)). | `Ticket.bonus`, `TankStats.setBonus` |

## 6. On the wire

| Term | Meaning | Where |
|---|---|---|
| **match traffic** | The traffic between a client and an arena. It is binary, and never goes through the gateway. On the site it goes through the **front**'s nginx on 9001, which ends its TLS and passes the bytes, unread, to the arena its **TLS name** names (D-82); or, without TLS, through 80, by that name (**match through 80**, D-115). | [02](detailed-design/02-networking.md) |
| **TLS name** | An arena's name on the private side of the front, such as `a1.arena.internal`. It is a grant's `tlsName`: the client's TLS handshake sends it (SNI, Server Name Indication) and checks the certificate against it, and the front's map turns it into that arena's private address and port. A client without TLS sends it in `/match/<name>` on 80 instead. The names are listed in `backend-arenas.conf` (the **list of arenas**), and are in no DNS. | `BACKEND_ADVERTISE_TLS_NAME`, `tlsName`, `$ssl_server_name` |
| **the backend's root** | The certificate authority of the backend's own, for a site with no domain. Its certificate, `ca.pem`, ships in the app, which trusts it alone; its key never goes on a server. It signs the one certificate nginx serves, which names the site's address and every **TLS name** ([operations/06](operations/06-certificates.md)). | `private-ca.sh`, `TrustRoot`, `/etc/backend/tls/ca.pem` |
| **lobby traffic** | The traffic between a client, the gateway and the platform: JSON over a WebSocket at `/lobby`, low in volume. | `LobbyHandler` |
| **kill feed** | Who killed whom, sent as `Kill` events: to the killer in every room, and to every player in a made match. A shape broken is not in it ([01 §9](detailed-design/01-arena.md#the-kill-feed-designed-2026-10-01-plan-item-37), Q-34). | `Wire.EVT_KILL`, `RoomThread.relayKills`, C# `MatchEvent.Victim` |
| **push** | A lobby message with no `id`, which the server sends unprompted, through the gateway that holds the player's connection. The gateway itself sends `evt.session.replaced`, and `evt.resync` to a slow client whose held pushes overflowed. `platform` sends `evt.session.revoked` when it ends every session of a player (a ban, a suspension or a deletion), `evt.match.found`, `evt.queue.update`, `evt.party.*`, `evt.team.update`, `evt.friend.*` and `evt.inbox`. `worker` sends `evt.tournament.match`, `evt.inbox` and `evt.rewards`. An operator's `evt.notice` goes to everyone, on `push:all`. A push is a notification: the client fetches the truth ([03 §7](detailed-design/03-gateway.md#7-what-must-not-be-lost)). | `evt.*` in [03](detailed-design/03-gateway.md), `LobbyPush`, `push:{gateway}` |
| **held push** / **resync** | A **held push** is one that the gateway keeps while the player's connection cannot take more: sixteen at most, sent in order when the connection drains. Past sixteen, the backlog is dropped, and one `evt.resync` is sent instead, telling the client to fetch the truth as after a reconnect. A connection that stays unwritable for 30 s is closed ([03 §8](detailed-design/03-gateway.md#8-backpressure-and-slow-clients)). | `gateway/Pushes`, `evt.resync` |
| **grant** | What a player is handed to go to a match: the arena's host and port, a single-use ticket, whether to use TLS, and the arena's **TLS name**. It is the answer to "play now", it is carried by `evt.match.found`, and it is kept for a tournament's call as `tgrant:`. | `JoinService.Grant`, `MatchQueue.Grant` |
| **notice** | An operator's message to everyone in the lobby, for example before a stop: `POST /admin/notice`, published once on `push:all`, and pushed as `evt.notice` ([04 §10](detailed-design/04-platform-services.md#10-admin-api)). | `AdminServer`, `evt.notice` |
| **protocol version** | The number that a `Join` names and the arena checks. It is raised when the wire changes in a way an older client cannot read; it has been 4 since the third class tier. An older client is refused with a kick. | `Wire.VERSION`, `Wire.KICK_PROTOCOL_VERSION` |
| **golden vector** | A snapshot frame and what it decodes to, written by the spike's independent codec. Both the server's reference decoder and the C# core must read it field for field: it is the contract between the two languages. | `protocol-spike/vectors/vectors.txt`, `GoldenVectorTest` |
| **welcome** | The first frame an arena sends after a join or a resume is accepted. It carries a new **resume secret**. | `Wire.MSG_WELCOME` |
| **kick** | A typed refusal, sent **before** the socket closes, so that the client can tell "get a new ticket" from "re-queue" from "update the app". | `Wire.MSG_KICK`, `KICK_*` |
| **event** | Something that happened, carried inside a snapshot rather than as a packet of its own. It is framed `type, byteLength, payload`, so an older client can skip a type it has never heard of. | `Wire.EVT_DEATH`, `EventBuffer` |
| **stats event** | A player's own level, experience and skill points. It is sent only to that player, and only when it changes: at once for a level or a spent point, and at most once a second for experience alone. | `Wire.EVT_STATS` |
| **prediction** (own tank) | The client moving its own tank by its own input at once, by a port of the room's movement rule, instead of waiting a round trip for the server to say where it went. Only the own tank is predicted; others are drawn a little in the past ([02 §9](detailed-design/02-networking.md#predicting-the-own-tank), D-62). | `OwnTank`, `TankMotion.Step` |
| **step** (client) | One tick of the own tank's prediction, at the room's 25 Hz. It is stamped with the seq of the input that will carry it, and holds the state after it. 64 steps are kept. | `OwnTank` |
| **reconciliation** / **replay** | What the client does with each frame: it puts the own tank where the server has it at the step that matches the frame's tick (**reconciliation**), then steps again through every step after it, each with its own input (**replay**). | `OwnTank` |
| **correction** | How far a reconciliation moved the predicted present. It is drawn away, halving every 50 ms. More than 64 units is a **jump** (a respawn, a resume), and is taken at once. | `OwnTank.DrawX` |
| **prediction error** | The matched step's position as predicted before the frame came, against the frame's position: what the drill measures. | `prediction` drill |
| **input ticks** | How many ticks the input that a frame echoes has driven the tank, up to the frame's tick: where in the input's span the tick fell. | `Motion`, `ClientView` |
| **motion event** / **motion rule** | Two events that carry state for the prediction, not news; the layer above never sees them. `Motion` (type 5) carries the input ticks and the own tank's velocity, in every frame while the tank lives. `MotionRule` (type 6) carries its acceleration and radius, as the server's floats, when either changes. | `Wire.EVT_MOTION`, `Wire.EVT_MOTION_RULE` |
| **ack tick** | The last snapshot the client fully applied, carried on every `Input`. It decides when a removed handle may be reused and whether a create has arrived ([02 §5](detailed-design/02-networking.md#5-entity-handles)), and shows how much is queued on the client's link, which steps its traffic profile ([D-17](architecture/03-decision-log.md#d-17--a-client-is-stepped-down-on-queueing-not-on-round-trip-time-or-writability)). It is **not** the delta baseline: deltas are against the last frame sent ([D-16](architecture/03-decision-log.md#d-16--deltas-are-measured-against-the-last-frame-sent)). | `Connection.takeAck`, `ClientView.acknowledge`, `TrafficControl.acknowledged` |
| **lifecycle** (client) | Whether the app is in the foreground. Going to the background parks the tank and stops its snapshots. **Unrelated** to a match's lifecycle. | `ClientMessage.LIFECYCLE` |
| **varint** | A variable-length integer encoding: one byte for anything under 128, which is nearly everything. | `SnapshotWriter.varint` |
| **traffic profile** | How much one client is sent: `high` 15 Hz and 60 entities, `mobile` 15 Hz and 30 (the default), `saver` 10 Hz and 20. The client names the most it wants in `Join` or `Resume`. The arena steps it down on a queueing link and back up, never above what was asked ([D-17](architecture/03-decision-log.md#d-17--a-client-is-stepped-down-on-queueing-not-on-round-trip-time-or-writability)). | `TrafficProfile`, `TrafficControl`, `Wire.PROFILE_*` |
| **round** (send) | One chance to send a client a snapshot, at its profile's rate. | `TrafficControl.round` |
| **held round** | A round not sent, because more than a second of snapshots is already queued on the link. The next frame just grows, since deltas are against the last frame sent. | `backend_arena_snapshots_held_total` |
| **floor** | The shortest acknowledgement delay a connection has shown. Queueing is measured above it. It never rises. | `TrafficControl` |

## 8. Words we do not use

| Instead of | Use | Why |
|---|---|---|
| the word the naming rules exclude, and its compounds | platform, match traffic, match mode, meta layer | The [naming rules](README.md#naming), which list them; they apply to prose and identifiers alike |
| combat, fight, round (as a unit of play) | match, open match, timed match | Vague, or already meaning something else. A tournament's round (FR-7) and a send **round** (§6) are fine |
| session (for time in an arena) | stay, or open match for its record | "Session" is the authenticated one |
| high score, hiscore, top score | best score | One name for the metric, and it matches the column |
| leaderboard period, era, bracket (of a leaderboard) | window | Three words had appeared for the same thing. A tournament's **bracket** (§5) is fine |
| stat point, upgrade point, talent | skill point | One name for the thing a level grants |
| skill tree, upgrade tree | tank tree | "Tree" is the class progression (**class**, **class tier**), not the stats |
| score (for a tank's current experience) | level, or experience | The score is the match's total and survives death; experience is the life's and does not |
| user | player, or account | Two different things, and "user" hides which |
| server (unqualified) | arena, gateway, platform, worker | Four different processes; "the server" names none of them |
| match (unqualified, when the kind matters) | open match / timed match | They behave differently, and are stored differently |
